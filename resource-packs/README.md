# Independent client resource packs

Texture/material packs and shader packs have their own Lattice package roots.
`profiles/resources.toml` selects them and `task lock:resources` writes their
separate `run/client-resources/latticeaxiom.lock`. The normal client verifies
this lock against the same CAS before applying presentation resources.

Set `LATTICEAXIOM_RESOURCE_LOCK` to select another already prepared resource
lock. Changing that lock never changes the gameplay lock, saved world header,
chunk generation inputs, inventory or collision. Source acquisition and CAS
verification reuse the package kernel; runtime appearance remains client-only.

`data/resource-pack.json` declares either `textures` or `shaders`. Texture rows
contain editable colors and procedural patterns, not binary images. Shader packs
provide WGSL for a versioned binding interface; water interface 1 matches the
host's material extension. Different kinds can be selected independently.
Higher explicit priority wins; equal-priority duplicate keys fail instead of
depending on directory discovery order. Changing resources requires a client
restart in this first implementation.

`packages/terrenia/presentation` retains semantic content-to-material and label
bindings. It is not the texture or shader payload store. The render-contracts
crate validates resource descriptors, and the actual presenter consumes them
for terrain, distant terrain, item thumbnails and the water shader.

Binary art is deliberately unversioned. Do not add images, models, audio or font
files, or encode their bytes into text. A dedicated art-management workflow is
deferred. Local runtime images generated by rendering code are not source assets.
