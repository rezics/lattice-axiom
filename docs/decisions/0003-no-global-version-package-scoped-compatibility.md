# 決策 0003：不以全域大版本決定相容性

## 背景

Lattice Axiom 由核心、演算法、內容、資產、工具與組態組成。這些部分會以不同速度演進；若以單一 `gameVersion`、`engineVersion` 或 `worldVersion` 作為相容性總開關，任何局部更新都會被誤報成整體不相容，也會迫使模組依賴與自身無關的發行節奏。

官方遊戲集合仍可有供發行、支援與人類溝通使用的版本，但它只是描述依賴的元套件版本，不代表所有內部能力共享同一版本，也不能取代實際依賴解析。

## 決策

1. Lattice Axiom 不設一個決定全部執行、網路、存檔與世界生成相容性的全域大版本。
2. 官方遊戲、伺服器規則集與整合包是宣告式組合設定檔或元套件；它們可以有自己的發行版本，但相容性由其實際依賴圖決定。
3. 每個套件獨立宣告套件版本、相依性範圍、提供與需要的能力契約，以及可選相依性。
4. 解析器產生鎖定圖，記錄精確套件版本、內容雜湊、來源、組態與所選能力提供者。清單描述允許範圍，鎖定圖描述這次實際解析結果。
5. 套件版本、能力契約版本、持久化 schema 版本與生成演算法修訂是不同識別軸，不得互相冒充。
6. 需要精確重現的演算法除了相容性版本外，還要有內容雜湊或等價的精確實現識別；相同語義版本不保證程序輸出逐位元相同。
7. 持久化資料由資料擁有者記錄自己的 schema 版本與遷移路徑，不由世界整體版本分派遷移分支。
8. 世界保存目前供新工作使用的已解析設定檔，並為生成計畫、規劃域、快取或其他持久化產物保存產物級生成記錄。
9. 產物級生成記錄只包含該產物真正依賴的子圖、組態與輸入識別；更新不相關模組不得使它失效。
10. 完整依賴圖可以有根雜湊，用於快速判斷「完全相同」；根雜湊不同只表示存在差異，不能單獨判定整體不相容。
11. 相容性解析輸出必須指出受影響的能力、資料、空間產物與所需動作，例如直接重用、重新計算、遷移、邊界轉接或拒絕載入。
12. 核心程式不得以官方集合版本撰寫 `if gameVersion >= ...` 一類相容性分支；它應查詢具名能力、契約版本或資料擁有者提供的遷移。

## 識別層次

| 識別 | 回答的問題 | 不負責的問題 |
| --- | --- | --- |
| 集合／元套件版本 | 使用者取得的是哪次官方或整合包發行？ | 內部所有能力是否相容 |
| 套件版本 | 某套件發布了哪個 API 與內容集合？ | 程序輸出是否完全相同 |
| 能力契約版本 | 提供者與使用者能否以同一語義交換資料？ | 套件如何部署或發布 |
| 內容雜湊／演算法修訂 | 能否精確識別這份實現與組態？ | 是否存在合法遷移 |
| 資料 schema 版本 | 某擁有者如何讀取與遷移其資料？ | 整個遊戲是否相容 |
| 產物生成記錄 | 哪個依賴子圖產生了這項空間或編譯產物？ | 世界中其他產物的狀態 |

## 世界演進

世界可以同時保存由不同但邊界相容的依賴子圖產生的規劃域。更新目前設定檔後：

- 已實體化且未要求遷移的舊產物保留自己的生成記錄。
- 新規劃域使用新的鎖定圖。
- 跨域地形、洞穴、水文與道路透過版本化邊界契約銜接。
- 若契約存在 adapter，可以局部轉接。
- 若差異會破壞跨域不變條件，解析器必須要求顯式遷移、保留舊提供者或拒絕該局部更新。

這不是「任何模組都可在任何時刻無縫熱換」的承諾，而是把不相容精確限制在真正受影響的依賴子圖與空間範圍。

## 結果

- 渲染器、洞穴形態、群系內容與存檔 schema 可以各自演進，不必等待共同大版本。
- 快取失效與重新生成可以沿依賴圖傳播，不必使整個世界作廢。
- 同一世界可能需要保留舊生成器或已物化基線；套件封存、內容定址取得與安全沙箱因此成為長期需求。
- 解析器與診斷工具比單一版本比較更複雜，但能說明實際差異與修復路徑。

## 被否決的方案

### 單一遊戲／世界版本門檻

它把無關變更綁在一起，無法描述局部能力相容，也鼓勵以條件分支累積歷史包袱。

### 只保存語義版本

相容 API 下的演算法修正仍可能改變程序輸出；沒有精確內容識別就無法重現或正確使快取失效。

### 只保存完整閉包雜湊

它能判斷兩個集合不完全相同，卻不能指出差異是否相關、能否遷移或只影響純表現內容。
