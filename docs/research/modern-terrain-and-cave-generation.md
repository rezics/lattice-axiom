# 現代地形與洞穴生成的演算法和硬體邊界

> 本頁整理候選技術、公開研究與由硬體資料推導的原型方向，不是效能承諾或演算法選型決策。所有數字都需要在 Lattice Axiom 的實際資料結構與目標硬體上重測。

## 主要進步不是新的萬能噪聲

近年的實用方向是把世界生成拆為：可控制拓撲、受語義或物理啟發的路徑、隱式幾何、稀疏取樣、多解析度實體化與玩法內容。

[2015 年的 GPU 洞穴生成研究](https://www.fdg2015.org/papers/fdg2015_paper_80.pdf)使用 L-System 建立裂隙與通道結構，再以受噪聲擾動的 metaball 雕刻體積並提取等值面。它證明骨架、形態與網格化可以拆成模組化管線。

[2021 年的地質一致洞穴研究](https://diglib.eg.org/items/a4e7985c-af52-4b55-bd1a-eeeff6c47422)進一步以入口、出口、斷層、初始層面、裂隙與滲透率建立各向異性代價，使用無網格最短路徑產生岩溶網路骨架，再以 SDF construction tree 實現通道。這直接支持「拓撲所有權、地質約束與局部形態分離」。

地表方面，[2024 年的解析式侵蝕研究](https://www-sop.inria.fr/reves/Basilic/2024/TGSC24/)顯示部分物理過程可以用解析近似取代大量時間步模擬；值得吸收的不是固定演算法，而是把昂貴物理轉成可局部查詢、可控制的生成算子。

## 現代桌面硬體基線

[Steam 2026 年 7 月硬體調查](https://store.steampowered.com/hwsurvey/)中，6 核和 8 核級別各約占 27%，16 GB 與 32 GB 記憶體合計占大多數，AVX2 支援率超過 95%。由此推斷，以 6 核、16 GB、AVX2 作為桌面 CPU 最佳化基線是合理候選，但仍需保留較低指令集與 ARM／NEON 路徑。

[FastNoise Lite 的公開比較](https://github.com/Auburn/FastNoiseLite)顯示，SIMD 化 FastNoise2 在較舊桌面 CPU 上也能達到每秒數億個簡單三維噪聲取樣點。這是函式庫自有基準，只能說明單純噪聲通常不是唯一瓶頸；真實成本還包括多場組合、空間索引、拓撲求解、網格化、快取與內容放置。

### 稠密體積的直觀成本

單一 `float32` 場約為：

```text
64³    = 1 MiB
128³   = 8 MiB
256³   = 64 MiB
1024³  = 4 GiB
```

因此可在鄰近區塊暫存 `64³` 或 `128³` 場，但不能對公里級規劃域建立逐米、多通道稠密體積。宏觀資料必須使用圖、解析場、稀疏磚、分層規劃與按需取樣。

## 候選洞穴拓撲

| 方法 | 優點 | 主要風險 | 建議角色 |
| --- | --- | --- | --- |
| 約束幾何圖 + 各向異性最短路徑 | 可保證目的地、入口、環路與地質方向 | 需要避免過度人工的圖形感 | 預設主幹候選 |
| Agent／場導引生長 | 有機、易形成分叉，可回應方向場 | 順序敏感，連通與目的地保證較難 | 第二個主幹原型或支線提供者 |
| L-System／Grammar | 容易創作可辨識的洞穴家族 | 全域約束與跨域銜接較弱 | 特殊群系或維度 |
| 裂隙網路／各向異性滲流 | 適合斷層、岩溶和迷宮形態 | 臨界參數敏感，玩法節奏難控制 | 地質群系局部拓撲 |
| 純 Perlin／Simplex／Worley 密度 | 快速、可無限查詢、適合細節 | 沒有顯式連通和目的地語義 | 形態與粗糙度，不作主幹 |
| WFC／局部約束拼接 | 擅長房間、遺跡與局部規則 | 三維無限網路的記憶體與邊界成本高 | 洞室內部和目的地 |
| 完整地下水／侵蝕模擬 | 物理因果較強 | 無限世界按需生成成本不可控 | 離線作者工具或有限特殊域 |
| 神經生成 | 可學習資料風格 | 約束、重現、診斷與模組互通較弱 | 作者候選工具，不作權威生成 |

## 建議的主幹原型

第一候選為 `ConstrainedGeometricGraphBackbone`：

1. 以父域入口、目的地、地下河端點和群系意圖建立必要 terminal。
2. 用具穩定鍵的帶權藍噪聲或領地取樣建立候選節點。
3. 用局部鄰接圖限制候選邊，避免完整圖的平方成本。
4. 先建立滿足必要 terminal 的連通森林，再按目標環路率、死路率、路徑伸展率與垂直度增加或刪除邊。
5. 以地質、水文、群系與保護體積組成各向異性路徑代價，把抽象邊嵌入三維空間。
6. 地下群系使用 SDF capsule、sweep、smooth union、warp 與局部原語實現形態。
7. 對實際幾何重新驗證淨空、連通、流體狀態和結構交集，失敗時只修復有界區域。

第二候選為 `FieldGrowthBackbone`，使用同步回合、穩定事件鍵與場導引 agent 生長，測試更自然但較難控制的模型。兩個候選必須使用相同的委派契約、入口、預算、生成記錄和評分器。

## 確定性與平行生成

[Random123](https://random123.com/releases/docs/)一類 counter-based RNG 把亂數表示為 key 與 counter 的無狀態函式，適合依世界種子、空間域、提供者、演算法修訂與語義用途建立互不干擾的亂數流。新增模組不能因多消耗一次全域 PRNG 而改變其他內容。

拓撲與入口應優先使用整數、量化座標和穩定排序。浮點 SDF 可以允許契約容差；若伺服器是權威來源，客戶端不需要跨 GPU 逐位元重建所有網格。

## CPU 與 GPU 分工

建議 CPU 權威地保存領地、拓撲、入口、穩定 ID、玩法語義與低解析度可通行驗證；GPU 只作可選的高密度場取樣、網格提取、視覺細節和編輯器預覽。如此可支援無 GPU 的伺服器，也避免不同 GPU 浮點結果成為存檔語義。

[NanoVDB](https://www.openvdb.org/documentation/doxygen/NanoVDB_MainPage.html)展示了緊湊、CPU／GPU 友好的唯讀稀疏體積表示，適合研究生成快取與渲染資料；其靜態拓撲限制意味著它不應直接被視為可破壞世界的唯一權威存儲。

[Transvoxel](https://transvoxel.org/)以 transition cell 銜接不同解析度的體素網格，可作洞穴、懸崖和拱門等體積地形 LOD 的候選實體化技術。

## 現代設備可做與不應做的事

### 可行候選

- 在背景執行每規劃域數百至數千節點的圖求解。
- 以多核心平行生成少量候選拓撲並用共同指標評分。
- 只在鄰近或被修改區塊取樣中高解析度 SDF。
- 使用 SIMD 編譯場圖，並以稀疏索引跳過無貢獻提供者。
- 在客戶端以 GPU 加速網格化，在伺服器保留 CPU 語義表示。
- 快取規劃域圖、入口與中間場，而不是保存整個稠密世界。

### 不適合作為基礎承諾

- 對多公里三維區域保存逐體素、多通道稠密資料。
- 每次載入區塊都重新求解整個跨區域洞穴網路。
- 以完整地下水或侵蝕時間步模擬驅動無限世界。
- 把 GPU-only、跨廠商逐位元一致當成權威生成前提。
- 使用無上限的搜尋或演化次數追求「最佳」拓撲。

## 原型量測

- 規劃、SDF 取樣、網格化與內容放置分項時間。
- 冷快取、熱快取、不同核心數與不同 SIMD 路徑。
- 圖上連通率、實際可通行率、環路秩、死路率與路徑伸展率。
- 群系拓撲辨識度、形態辨識度與跨域入口誤差。
- 稠密暫存峰值、稀疏索引大小、網格頂點數與傳輸量。
- 打亂區塊順序、工作排程與模組註冊順序後的結果一致性。
