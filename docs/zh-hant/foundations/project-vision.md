# 專案願景與設計支柱

## 一句話願景

Lattice Axiom 探索一種「遊戲本身就是模組組合結果」的遊戲架構：核心提供可組合的機制，官方內容與第三方內容透過相同能力加入遊戲，而建置與執行系統把這些描述整理成可高效執行的形式。

這是目前從對話中提煉出的架構願景，不是完整的遊戲願景。玩法類型、玩家體驗、世界觀與商業模式仍未定義。

## 暫定設計支柱

### 核心保存機制，內容由模組提供

核心應理解「實體、元件、系統、世界區塊、物品、材質、碰撞與渲染基元」等一般機制，而不需要內建「殭屍、森林、鑽石劍」等具體內容。

### 官方內容與第三方內容使用同一條公開路徑

Vanilla 內容不應依賴第三方無法使用的私有能力。官方內容本身應成為模組 API 的整合驗證。

### 組合方式與執行方式分離

模組可以由宣告式配置、套件管理器、靜態建置或資料夾掃描被發現；也可以被靜態連結、動態載入、沙箱執行或直譯。這兩組選擇不應混為一談。

### 作者描述性質，通用機制產生反應

內容作者盡量描述「這是什麼、具有什麼性質與能力」，而不是為每種情境手寫結果。例如作者標記龍腹部的柔軟度，通用物理與表現模組再根據碰撞產生局部形變。

### 擴充邊界應在熱路徑之前被消化

模組在發現、解析與註冊時保有模組身分；進入遊戲迴圈後，應盡可能轉成資料、數值識別碼、連續記憶體、系統排程、函式指標、渲染批次或已編譯管線。

## 尚未形成的產品定義

以下問題不能由目前這段架構討論回答：

- 玩家每分鐘實際做什麼？
- Lattice Axiom 是一款遊戲、一個可組合遊戲平台，或兩者兼具？
- 哪種玩法最能證明模組架構對玩家有價值？
- 官方內容包的最小可玩範圍是什麼？
- 開放創作、多人一致性、安全性與效能之間如何排序？

這些問題集中在[待決問題](../planning/open-questions.md)，應在架構選型之前或同時推進。
